# easyssh-proto

The single JSON Schema contract between the future `easysshd` daemon and the
UI (see `docs/architecture-v2.md`, sections 2 to 4). It is enforced at the `easysshd`
boundary and by its client. The crate is transport-agnostic: a message is a JSON value, and how it
travels is somebody else's concern.

## Contents

- `schema/proto.schema.json`: JSON Schema draft 2020-12, one document with
  everything under `$defs`.
  - Entities in exactly the shape v1 serializes today (`AppConfig`,
    `Connection`, `ConnectionTarget`, `Group`, `CommandSnippet`, `Tunnel`,
    `TerminalPreferences`, `SidebarPreferences`, and the types they use).
    Fields with `#[serde(default)]` in `easyssh-core` are optional; everything
    else v1 writes is required, nullable fields included.
  - Envelopes: `Command`, `Event`, `Reply`, `ProtoError`, `SchemaVersion`.
  - Commands and events: `proto.hello`, `hosts.list|save|delete`,
    `session.open|write|resize|close|list|attach|detach`,
    `askpass.reply|endpoint`, `daemon.shutdown_when_idle`; events
    `session.output` (optional per-session byte offset `seq`), `session.exit`,
    `askpass.prompt`, `askpass.resolved`, `hosts.changed`. It will grow.
    `proto.hello` carries `schema_version` (any integer, so a daemon can answer
    a mismatch with `schema_mismatch`) and the build's `app_version`;
    `session.open` accepts the client's `ssh_auth_sock`; `hosts.save` accepts
    a `group` to create.
- `src/generated.rs`: Rust types generated by `typify`, checked in.
- `src/lib.rs`: `validate(schema_name, &Value)`, `validate_command`,
  `validate_event`, the `COMMANDS` / `EVENTS` tables and `SCHEMA_VERSION`.
- `../../src/lib/proto.gen.ts`: TypeScript types generated by
  `json-schema-to-typescript`, checked in.

Message naming: entities keep v1's snake_case field names; the new command
and event payloads use snake_case too.

## Regenerating

Edit the schema, then:

```sh
UPDATE_PROTO=1 cargo test -p easyssh-proto --test codegen   # src/generated.rs
npm run gen:proto                                           # src/lib/proto.gen.ts
```

Builds never run codegen. `cargo test -p easyssh-proto` regenerates in memory
and fails when `src/generated.rs` is stale. For the TypeScript file, re-run
`npm run gen:proto` and check `git diff` is empty.

`tests/v1_compat.rs` serializes real `easyssh-core` values and validates them
against the schema; run it after any change to either side.

## Versioning

`SCHEMA_VERSION` (and the `SchemaVersion` const in the schema) names the
protocol version. Within one version only **additive** changes are allowed:
new optional fields, new commands and events, new enum values only where
every consumer already treats unknown values safely. Removing or renaming a
field, making an optional field required, or changing a type needs a new
`schema_version`. Objects set `additionalProperties: false`, so client and
daemon are expected to ship the same schema revision and compare
`schema_version` with `proto.hello` on connect.

`AppConfig.schema_version` is the unrelated v1 storage version (currently 7).
